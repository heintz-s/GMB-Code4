Relational Databases

Databases

Databases are structured systems for managing data. They enable efficient access, storage, and manipulation of large amounts of data.

Requirements for Databases

Typical requirements for modern databases include:

  • Handling large amounts of data: Optimal management and scalability.
  • Fast access: Minimal latency for queries.
  • Concurrent access: Support for multiple simultaneous users.
  • Consistency: Ensuring data integrity (= correctness of data).
  • Security: Protection against unauthorized access and data loss.
Database Management System (DBMS)

A Database Management System (DBMS) is software that controls the management and access to data in a database.

CRUD Operations

Persistent storage usually offers four basic operations for managing stored data:

  • Create: Add new records.
  • Read: Retrieve records.
  • Update: Modify existing data.
  • Delete: Remove records.

These operations are abbreviated as CRUD according to their initial letters.

Transactions

A transaction consists of one or more logically related operations that should be executed as a unit.

Example: Money transfer – debit from account A and credit to account B.

  • Update operation: Reduce money in account A by the transfer amount
  • Update operation: Increase money in account B by the transfer amount

If an error occurs in any operation, the entire transaction is rolled back and the original state is restored.

ACID Properties
  • Atomicity
    • All operations of a transaction are fully executed or rolled back.
    • Example: Money debited from account A is guaranteed to arrive in account B (or is not debited at all).
  • Consistency
    • After a transaction, the data must always be in a valid state according to defined rules.
    • Example: An account cannot be overdrawn if this is not allowed.
  • Isolation
    • Concurrent transactions do not affect each other. They must lead to the same result as if they were executed sequentially.
    • Example: Two users book a cinema seat. It must be ensured that the same seat is not assigned multiple times.
  • Durability
    • Successfully completed transactions remain permanently stored, even in case of system failures.
    • Example: An order remains safely stored after completion.

Relational Databases

Basics

Relational databases structure data in tables. Each table consists of:

  • Rows: A single record.
  • Columns: Properties to be stored for each record.
  • Primary Key: To access individual records, there must be a unique identifier. This can be a single property, often an auto-incrementing ID, or a combination of properties.
  • Foreign Key: Tables can be linked via the primary key. The primary key is included as a property in another table.

Normalization

Normalization reduces redundancy. If the same value is not stored multiple times, this prevents inconsistent information.

Example: “Business, Design & Media” appears multiple times in the table below and could be entered as “Faculty 4” in one place and as “Business, Design & Media” in another.

The first three of five stages of normalization include:

  1. Normal Form:
    • Columns contain only single values.
    • Example: Split name into first name and last name.
  2. Normal Form:
    • Table represents only one subject.
    • All properties depend entirely on the primary key.
    • Example: Student and lecture in separate tables, as the lecture does not depend on the student ID.
  3. Normal Form:
    • Tables should only contain direct dependencies.
    • Non-key properties must not depend on each other.
    • Example: Course and faculty are dependent on each other and should be in separate tables. StudentID -> Course and Course -> Faculty 1

Setting up SQLite

A SQLite database consists of a single file:

  • Create a file named dbName.db in the project folder (choose a suitable database name)
  • Install the SQLite Plugin in VSCode
    • Select the SQLite file in the project to view it
    • Show and Run Commands -> CTRL + SHIFT + P
    • SQLite: New Query -> enter SQL commands
    • SQLite: Run Query -> select SQLite file -> executes SQL commands and shows results
  • Optional: Download DB Browser for SQLite
    • Open SQLite file to view
    • Use the Execute SQL tab to enter and execute SQL commands
