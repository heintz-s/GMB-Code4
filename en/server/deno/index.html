Deno Server

Deno

Deno is a modern runtime environment for JavaScript and TypeScript that allows you to run TypeScript/JavaScript outside the browser. It was developed by the original Node.js creator Ryan Dahl to fix design flaws in Node.js and offers a secure and modular environment. Node.js still has a much larger community and more available packages.

  • Developed by: Ryan Dahl
  • Technical basis: Chrome’s V8 JavaScript/TypeScript engine
  • Strengths: Can handle many parallel requests quickly with low memory usage. Security through restrictive access to files, network, and environment by default; native TypeScript support; modern API.
  • Use cases: Real-time communication (chats, streaming); access to object data; less suitable for compute-intensive tasks.
  • Extensibility: Lightweight, modular, many standard modules available. No central package management required, modules can be imported directly via URL.

Deno Modules

Deno can be extended with external modules that are loaded directly from URLs. There is no central package manager like npm ; modules are imported via URL.

  • Function: Import modules directly from the internet, local modules, or the standard library. Once loaded, modules remain in the cache.
  • Advantages:
    • No dependency on package managers.
    • No local management of modules and their versions required (as with Node.js). A module with the desired version is loaded directly via URL.

Installation and First Project

  1. Install Deno:

    • Follow the instructions at deno.land .

  2. Check installation:

    • Run deno --version in the command line.

  3. “Hello World” server with TypeScript:

  4. Start the server:

    • Open the command line
    • Run deno run --allow-net server.ts (allow network access)

  5. Send a request to the server:

    • In the browser address bar: http://localhost:3000 or http://127.0.0.1:3000
    • via JavaScript/TypeScript in a web application: fetch("http://localhost:3000")

  6. Stop the server:

    • In the command line with: Ctrl+C
    • Can also stop due to errors: watch the output in the command line

  7. Restart the server after code changes

URL

The server usually provides a variety of functionalities (e.g., storing, retrieving, editing different data). To determine which function should be addressed, it needs the URL.

Components of a URL

Protocol: Communication protocol (e.g., https). Hostname: Domain or IP address. Port: Allows multiple services on a host (e.g., port 443 for HTTPS). Path: Requested resource (e.g., /index.html). Search: Parameters (e.g., ?q=nodejs). Hash: Anchor in the document (e.g., #section1).

  • Protocol: Protocol used for communication (e.g., https)
  • Hostname: Domain name or IP address
  • Port: Allows multiple services on a host
  • Path: Requested resource (can correspond to a file path)
  • Search: Parameters with values that are sent along
  • Hash: HTML element ID to jump to (usually not relevant for the server)

JavaScript URL API

The URL API allows you to break down URLs into their components. This allows the server code to examine the URL of the request from the client.

Deno: Dynamic Routes

The server can provide different functions. The request URL or method can be used to determine which function should be executed.

  1. Path in the request URL:

    • Depending on the URL path, different code is executed on the server.
    • The path is determined using the URL API.
    • The server responds to different paths with queries such as if/else or switch case.

  2. Request Method

    • Different HTTP methods (GET, POST) execute different server code.
    • The request object can be used to access the method.
    • The server responds to different methods with queries such as if/else or switch case.

Additionally, individual information can be transmitted via search parameters or integrated into the path to specify the request.

  1. Search Parameters

    • Information can be passed via search parameters in the URL.
    • Example: https:localhost:3000/item?id=123 to request an item with ID 123

  2. Integration into Path

    • Information can be integrated into the path, such as an ID. These must then be extracted from the path in the server code.
    • Example: https:localhost:3000/item/123 to request an item with ID 123

Deno GET/POST Requests

The request can be handled differently depending on the request method, even with the same URL. This can of course also be combined with a query on the path.

  • GET: Data is retrieved from the server.
  • POST: Data is sent to the server (e.g., JSON, files).
    • The data arrives in chunks (stream) and must be reassembled.
    • Extensive data can be sent, such as object data in JSON format, or files (unlike sending individual information via search parameters or URL path).
