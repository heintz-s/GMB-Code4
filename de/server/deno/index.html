Deno Server

Deno

Deno ist eine moderne Laufzeitumgebung für JavaScript und TypeScript, die es ermöglicht, TypeScript/JavaScript außerhalb des Browsers auszuführen. Sie wurde vom ursprünglichen Node.js-Erfinder Ryan Dahl entwickelt, um Designfehler von Node.js zu beheben und bietet eine sichere und modulare Umgebung. Node.js hat hingegen bislang eine deutlich größere Community und mehr verfügbare Pakete.

  • Entwickelt von: Ryan Dahl
  • Technische Basis: Chromes V8 JavaScript/TypeScript Engine
  • Stärken: Kann schnell viele parallele Zugriffe verarbeiten bei geringem Speicherbedarf. Sicherheit durch standardmäßig restriktiven Zugriff auf Dateien, Netzwerk und Umgebung; native TypeScript-Unterstützung; moderne API.
  • Einsatzbereiche: Echtzeit-Kommunikation (Chats, Streaming); Zugriff auf Objektdaten; weniger geeignet für rechenintensive Aufgaben.
  • Erweiterbarkeit: Schlank, modular aufgebaut, zahlreiche Standardmodule verfügbar. Keine zentrale Paketverwaltung nötig, Module können direkt per URL importiert werden.

Deno Module

Deno kann durch externe Module erweitert werden, die direkt von URLs geladen werden. Es gibt keinen zentralen Paketmanager wie npm ; Module werden per URL importiert.

  • Funktion: Importieren von Modulen direkt aus dem Internet, lokale Module oder Standardbibliothek. Einmal geladene Module verbleiben im Cache.
  • Vorteile:
    • Keine Abhängigkeit von Paketmanagern.
    • Kein lokales Management von Modulen und deren Versionen nötig (wie bei Node.js). Es wird über die URL direkt ein Modul mit gewünschter Version geladen.

Hinweis

Deno ist von Haus aus sicherheitsbewusst. Deshalb muss der Server mit dem Flag -A (All Permissions) gestartet werden, um vollen Netzwerkzugriff zu ermöglichen. In einer Produktionsumgebung sollten die Berechtigungen jedoch restriktiver gesetzt werden, zum Beispiel nur für den Netzwerkzugriff mit --allow-net.

URL

Der Server soll in der Regel eine Vielzahl an Funktionalitäten bereitstellen (z. B. unterschiedliche Daten speichern, abrufen, bearbeiten). Um festzustellen, welche dieser Funktionen angesprochen werden soll, benötigt er die URL.

Bestandteile einer URL

Protokoll: Kommunikationsprotokoll (z. B. https). Hostname: Domain oder IP-Adresse. Port: Ermöglicht mehrere Dienste auf einem Host (z. B. Port 443 für HTTPS). Pfad: Angeforderte Ressource (z. B. /index.html). Suche: Parameter (z. B. ?q=nodejs). Hash: Anker im Dokument (z. B. #section1).

  • Protokoll: Zur Kommunikation verwendetes Protokoll (z. B. https)
  • Hostname: Domainname oder IP-Adresse
  • Port: Ermöglicht mehrere Dienste auf einem Host
  • Pfad: Angeforderte Resource (kann Dateipfad entsprechen)
  • Suche: Parameter mit Werten die mitgesendet werden
  • Hash: HTML Element ID, zu der gesprungen wird (normalerweise nicht für Server relevant)

JavaScript URL API

Die URL API ermöglicht es URLs in ihrer Bestandteile zu zerlegen. Damit kann im Server Code die URL des Requests vom Client untersucht werden.

Deno: Dynamische Routen

Der Server kann verschiedene Funktionen zur Verfügung stellen. Über die Request URL oder Methode kann festgestellt werden, welche der Funktionen ausgeführt werden soll.

  1. Pfad in Request URL:

    • Je nach URL-Pfad wird unterschiedlicher Code auf dem Server ausgeführt.
    • Mit der URL API wird der Pfad ermittelt.
    • Der Server reagiert mit Abfragen wie if/else oder switch case auf unterschiedliche Pfade.

  2. Request Methode

    • Unterschiedliche HTTP-Methoden (GET, POST) führen verschiedene Server-Codes aus.
    • Über das request Objekt kann auf die Methode zugegriffen werden.
    • Der Server reagiert mit Abfragen wie if/else oder switch case auf unterschiedliche Methoden.

Zusätzlich können einzelne Informationen über Suchparameter übermittelt oder in den Pfad integriert werden, um die Anfrage zu präzisieren.

  1. Suchparameter

    • Informationen können über Suchparameter in der URL übergeben werden.
    • Beispiel: https:localhost:3000/item?id=123 zur Abfrage eines Items mit der ID 123

  2. Integration in Pfad

    • Es können Informationen in den Pfad integriert werden, wie zum Beispiel eine ID. Diese müssen dann im Server Code wieder aus dem Pfad extrahiert werden.
    • Beispiel: https:localhost:3000/item/123 zur Abfrage eines Items mit der ID 123

Deno GET/POST-Anfragen

Die Anfrage kann bei gleicher URL je nach Request Methode unterschiedlich bearbeitet werden. Dies kann natürlich auch mit einer Abfrage auf den Pfad kombiniert werden.

  • GET: Daten werden vom Server abgerufen.
  • POST: Daten werden zum Server gesendet (z.B. JSON, Dateien).
    • Die Daten kommen in Stücken an (Stream) und müssen wieder zusammengesetzt werden.
    • Es können umfangreiche Daten gesendet werden, zum Beispiel Objektdaten in JSON Format, oder Dateien (im Gegensatz zum Senden von einzelnen Informationen über Suchparameter oder URL Pfad).
